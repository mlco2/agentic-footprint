# Release process

Releases are produced only from tags matching `v*.*.*`.

## Maintainer checklist

1. Ensure the working tree is clean and CI passes on the release commit.
2. Update every workspace package version and `Cargo.lock`.
3. Review user-facing documentation and release notes.
4. Create and push an annotated tag, for example `v0.1.0`.
5. Review the GitHub release artifacts, checksums, Sigstore bundles, and build
   provenance generated by `.github/workflows/release.yml`.
6. Verify at least one archive using the published verification guide.

## Reproducibility controls

- `rust-toolchain.toml` pins the Rust compiler and required components.
- Cargo builds use `--locked` and disable incremental compilation.
- The console uses `npm ci` and the committed lockfile.
- Every binary is built twice in independent target directories and compared
  byte-for-byte before packaging.
- Release archives use sorted entries, fixed ownership, fixed permissions, and
  `SOURCE_DATE_EPOCH` as their timestamp.
- Checksums, keyless signatures, and GitHub provenance are attached to the
  release.

The comparison proves repeatability inside the pinned release runner image. A
future higher-assurance step can add independent builders and compare their
outputs across infrastructures.
